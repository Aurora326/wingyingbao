00文档说明

本方案面向上海某城投国企集团下属、以地产开发运营为主业的子公司，目标是在现有银行账户采集与对账平台基础上，建设一套“看得见、说得清、管得住”的司库资金管理平台。

方案的重点不是把所有银行功能一次性搬上线，而是先解决这类客户最现实的问题：账户多、专户多、项目多、受限资金多，账面余额与可用资金不清，资金日报靠手工，专户监管和项目资金缺口缺少统一视图。

方案主线：先做“资金专户台账 + 项目资金视图 + 资金日报”，再做“资金计划与审批”，最后才做“支付、银企直连、融资与票据”。这条路径能在较低风险下先产生管理价值。

适用读者

客户分管财务的领导、资金/财务部门、项目财务、信息化部门、审计与风控部门；乙方的产品、实施、研发、测试与运维团队。

已知背景与待确认事项

本方案基于目前已知的客户背景编写。以下内容需要在项目启动调研阶段确认：集团与子公司的组织层级、银行账户清单、资金专户类型及监管要求、项目清单、现有财务/ERP/OA 系统、银行直连条件、历史数据范围、审批制度与权限边界。

关键结论

  • 专户优先：资金专户不是普通账户的一个标签，而是独立的监管台账，必须单独管理监管方、受限金额、最低留存和释放条件。
  • 项目维度：地产业务的资金管理必须按项目看回款、工程支出、土地款、税费、利息和资金缺口。
  • 三分余额：账面余额、可用余额、受限/监管资金必须分开呈现，避免“账上有钱但不能用”的误判。
  • 先查询后支付：一期不做支付，先把账户、余额、流水、回单、专户和报表做准；支付涉及银行直连、审批、安全和双人复核，放到二期。
  • 复用现有底座：现有 UKey/Agent 采集、任务调度、流水、回单、对账、租户隔离和审计能力可以继续使用，避免重复建设。

01项目背景与客户画像

1.1 客户背景

客户为上海某城投国企集团下属子公司，主业与地产开发相关，通常同时承担项目公司、区域公司或专业公司的资金管理职责。其资金管理既受集团统一管控，又受项目监管、国资监管和银行账户管理制度约束。

1.2 业务特征

特征对司库的含义
城投国企子公司需要集团—子公司—项目公司的多级资金视图，强调账户备案、审批留痕、审计可追溯和国资监管报表。
地产开发业务资金按项目全周期流动：土地款、开发贷、销售回款、工程款、税费、利息、股东借款，必须按项目核算和预测。
资金专户多预售资金监管户、农民工工资专户、拆迁补偿专户、项目资本金专户、专项债/财政资金专户、共管账户等，资金使用受监管方和项目节点约束。
集团管控需要合并余额、资金集中度、内部往来、统借统还、担保和融资台账，支持集团资金调度。
合规要求高“三重一大”、账户开立/变更/撤销审批、UKey 双人保管、大额资金联签、审计留痕，都是司库系统必须承载的流程。

1.3 典型痛点

痛点现状表现管理影响
账户分散各项目公司、各银行账户分散，账户清单靠 Excel 维护。无法快速掌握账户总数、状态、UKey 保管人和采集覆盖情况。
专户不清专户类型、监管方、受限金额、最低留存、释放条件记录不清。可能误用监管资金，无法及时准备释放材料，审计解释成本高。
可用资金不清只看到账面余额，看不到受限金额和可用余额。集团或公司层面误判资金余量，影响资金调度和项目支付。
项目资金不清余额、回款、工程支出、土地款、税费没有按项目归集。项目资金缺口发现晚，依赖财务手工统计。
计划执行弱资金计划在 Excel 中编制，实际执行靠人工比对。计划与实际脱节，无法提前发现偏差。
报表靠手工资金日报、专户台账、账户清单需要多人重复整理。时效性差、口径不一致、数据难追溯。
预警缺失专户低于留存线、账户长期未更新、证书到期等靠人盯。风险发现滞后，采集失败可能影响资金判断。

1.4 建设诉求

客户需要的不是“再多一个网银查询页面”，而是一套能够回答以下问题的司库工作台：

  • 集团/公司/项目现在有多少钱？其中多少可用、多少受限？
  • 每个资金专户的监管要求是什么？当前是否满足最低留存和释放条件？
  • 每个地产项目的回款、支出、资金缺口和到期债务是什么情况？
  • 资金计划执行到什么程度？偏差在哪里？
  • 哪些账户、专户、证书、采集任务存在风险？
  • 这些数据从哪里来、什么时候更新、谁看过、谁改过？

02建设目标与范围

2.1 总目标

建设一套面向城投地产子公司的司库资金管理平台，以银行账户和资金专户为基础，以项目资金为主线，以资金日报和风险预警为抓手，形成“账户全、余额准、专户清、项目明、报表快、风险早”的资金管理能力。

2.2 司库 1.0 目标

序号目标验收口径
1账户全生命周期可见所有银行账户纳入平台，记录账户性质、状态、所属公司/项目、UKey、证书和采集状态。
2资金专户台账化专户类型、监管方、受限金额、最低留存、释放条件、最近采集可查。
3余额三分账面余额、可用余额、受限/监管资金分列，支持集团/公司/项目汇总。
4项目资金视图按项目查看余额、回款、支出、资金缺口和近期到期事项。
5资金日报自动化每日自动生成资金日报，支持 PDF/Excel 导出。
6风险预警专户留存、监管资金、采集失败、证书到期、大额交易等规则可配置。

2.4 设计原则

  • 专户优先：先解决资金专户的监管属性，再谈账户余额汇总。
  • 项目维度：所有资金数据尽可能落到项目，支持地产项目全周期管理。
  • 三分余额：账面、可用、受限必须分开，报表口径统一。
  • 先查询后支付：一期不碰支付，降低银行接口、审批和安全风险。
  • 数据可追溯：每条余额、流水、专户数据都要有来源、采集时间和操作审计。
  • 复用现有底座：UKey/Agent 采集、任务调度、流水、回单、对账、租户隔离继续使用。

5.2 账户与专户

  • 账户台账：账户名称、账号、开户行、账户性质、所属公司/项目、状态、UKey、证书、采集状态、最近余额。
  • 账户生命周期：开户、变更、冻结、久悬、销户；记录审批单号、经办人、附件。
  • 专户台账：专户类型、监管方、监管银行、账面/可用/受限、最低留存、释放条件、最近释放、下次复核。
  • UKey 保管：UKey 编号、保管人、交接记录、证书到期、绑定设备。

5.3 项目资金

以地产项目为主线，汇总项目公司、项目账户、专户和资金流水：

  • 项目余额：账面、可用、受限。
  • 项目回款：销售回款、按揭放款、预售监管释放。
  • 项目支出：土地款、工程款、材料款、税费、利息、营销费用。
  • 资金缺口：未来 30/60/90 天预计支出与可用资金对比。
  • 项目风险：监管资金不足、回款不及预期、工程款集中支付、债务到期。

5.4 资金计划（一期可选，二期完整）

功能说明
计划编制按年度/月度/周编制，按公司、项目、账户、收支类别拆分。
计划审批资金计划提交、审核、下达；支持版本和调整记录。
执行跟踪实际流水自动归集到计划项，计算执行率、差异、偏差原因。
资金缺口计划支出 - 可用资金 - 预计回款，形成未来资金缺口。

5.5 收支、回单与对账

复用现有采集与对账能力，补充司库需要的维度：

  • 流水增加项目、收支分类、用途、交易后余额、专户标识。
  • 回单与流水、付款申请、内部单据关联。
  • 对账结果进入资金日报和风险预警，未对账流水按账龄展示。
  • 支持按公司、项目、账户、专户、收支类别筛选和导出。

5.6 风险预警

预警规则示例处理建议
专户低于留存线可用余额 < 最低留存，或账面余额 < 监管最低额度提示补足、调整支付计划、联系监管银行。
监管资金异常专户支出超出监管用途，或受限金额突然下降复核支付用途、监管释放材料、审计留痕。
大额交易单笔或当日累计超过阈值推送财务负责人、资金负责人复核。
数据不及时账户超过 N 小时未更新，或采集任务连续失败检查 UKey/Agent/网络，触发重试。
证书到期UKey 证书 30/15/7 天内到期安排更新，避免采集中断。
融资/债务到期贷款、票据、担保 30 天内到期纳入资金计划，提前安排还款。

5.7 报表中心

一期提供六类报表，支持按权限查看、PDF/Excel 导出、按日/月归档：

  1. 资金日报
  2. 资金专户监管台账
  3. 项目资金表
  4. 账户清单
  5. 收支明细与分类汇总
  6. 采集健康度/数据质量报表

5.8 系统管理

  • 组织与项目维护、账户主数据维护、专户规则维护。
  • 用户、角色、数据权限、审批权限。
  • UKey/Agent/设备/采集任务运维。
  • 审计日志、操作记录、数据导出记录。

06资金专户管理专篇

6.1 专户类型

专户类型典型监管方管理重点
预售资金监管户住建部门/监管银行监管额度、工程节点释放、按揭放款归集、可用余额。
农民工工资专户人社部门/银行人工费拨付、实名制、工资代发、不得挪用。
拆迁补偿专户属地政府/街道补偿对象、发放进度、结余资金。
项目资本金专户银行/集团资本金到位、使用范围、项目匹配。
专项债/财政资金专户财政/发改/审计专款专用、支出进度、绩效与审计。
共管账户合作方/银行共管比例、双方签章、支付条件。
开发贷专户贷款银行贷款发放、受托支付、还款计划。
保证金/保函户银行/合作方保证金余额、到期释放、保函对应关系。

6.2 专户台账字段

字段说明
所属公司/项目专户归属的法人主体和地产项目。
专户类型预售监管、农民工工资、拆迁补偿、项目资本金、专项债、共管、开发贷、保证金等。
监管方住建、人社、财政、街道、银行、集团等。
开户行/账号银行、支行、账号、账户名称。
账面余额银行账面余额。
受限金额监管冻结、最低留存、共管冻结等不可用金额。
可用余额账面余额 - 受限金额，必要时考虑最低留存和透支额度。
最低留存监管要求的最低余额或留存比例。
释放条件工程节点、监管额度、审批材料、合作方签章等。
最近释放/下次复核释放日期、金额、下次复核日期。
状态正常、预警、冻结、已销户。

6.3 可用资金计算

建议口径：可用余额 = 账面余额 - 受限金额 - 最低留存 + 可透支/授信额度（如适用）。不同银行/监管方的口径可能不同，系统应支持按账户配置公式或人工调整，并保留调整原因和审计记录。

6.4 专户预警

  • 账面余额低于监管最低留存。
  • 可用余额为负或低于未来 7 天计划支出。
  • 专户支出用途与监管类型不匹配。
  • 专户超过 N 天未采集或余额长期不动。
  • 监管释放节点临近但材料未准备。
  • 专户未纳入平台采集，或 UKey 未绑定。

6.5 专户报表

  • 专户监管台账（按公司/项目/类型）。
  • 专户余额与可用资金日报。
  • 专户收支明细。
  • 预售监管资金释放台账。
  • 农民工工资专户拨付台账。
  • 专户异常与待办清单。

07数据模型改造

7.1 模型关系

OrgUnit（集团/公司/项目公司/部门） │ 1:N Project（地产项目） │ 1:N BankAccount（银行账户）── 1:1 ── SpecialAccount（专户台账） │ 1:N │ BalanceSnapshot（余额快照） Statement（流水） │ │ └──────── ReportSnapshot ─────────┘ FundPlan（资金计划）── FundPlanItem（计划明细） Alert（预警）── AccountEvent（账户事件）── AuditLog（审计）

7.2 新增与扩展模型

模型处理关键字段
OrgUnit新增tenant_id、parent_id、code、name、type（集团/公司/项目公司/部门）、legal_entity_id、status。
Project新增tenant_id、org_id、code、name、stage、location、total_investment、pre_sale_status、start_date、end_date。
BankAccount扩展org_id、project_id、account_type、special_type、regulator、supervision_bank、opening_date、closing_date、status、is_restricted、min_balance、parent_account_id、cash_pool_code、direct_connect_status、ukey_custodian、approval_doc_no。
BalanceSnapshot扩展book_balance、available_balance、restricted_balance、min_balance、overdraft_limit、cutoff_at、source、is_continuous。
SpecialAccount新增account_id、project_id、special_type、regulator、restricted_balance、available_balance、min_balance、release_condition、release_node、last_release_date、next_review_date、status。
Statement扩展project_id、category、purpose、balance_after、special_fund_flag、recon_status。
FundPlan / FundPlanItem新增（二期）period、org_id、project_id、account_id、category、direction、planned_amount、actual_amount、variance、status。
AlertRule / Alert新增rule_type、scope、threshold、level、status、handled_by、handled_at。
ReportSnapshot新增report_type、report_date、scope、payload、generated_at、generated_by。
AccountEvent新增account_id、event_type、event_date、approval_doc_no、operator、attachment、remark。

7.3 迁移策略

  • 现有 Enterprise 保留为法人主体，新增 OrgUnit 表达集团—公司—项目公司层级。
  • 现有 BankAccount 新增字段允许为空，按账户清单逐步补全组织和项目。
  • 现有 BalanceSnapshot 增加可用/受限字段，历史数据先按账面余额回填。
  • 现有流水/回单/任务数据保留，新增项目、分类字段后逐步回填。
  • 生产环境从 SQLite 迁移到 PostgreSQL，使用 Alembic 管理版本；迁移前做全量备份和回滚演练。

08报表体系

报表频率主要读者核心内容
资金日报每日集团/公司资金负责人账面、可用、受限、今日收支、异常、专户摘要。
资金专户监管台账每日/每周财务、项目、审计专户类型、监管方、余额、受限、最低留存、释放条件。
项目资金表每周/每月项目财务、公司领导项目余额、回款、支出、缺口、到期债务。
账户清单每月/按需财务、审计、IT账户性质、状态、UKey、证书、采集覆盖。
收支明细/分类汇总每日/每月财务、项目按公司、项目、账户、类别汇总收入支出。
资金计划执行表每月资金负责人计划、实际、差异、执行率、偏差原因。
采集健康度每日运维、财务采集成功率、数据新鲜度、失败任务、证书到期。
融资/担保/票据台账每月资金、审计授信、贷款、担保、票据、到期日、成本。

8.1 报表口径

  • 所有报表必须带“数据截止时间”和“数据来源”。
  • 余额口径统一为账面、可用、受限三列；专户报表增加最低留存和释放条件。
  • 集团汇总时区分“全口径”和“可调度口径”，避免把监管资金算作可调度资金。
  • 报表支持按权限导出 PDF/Excel，并记录导出人和导出时间。

09权限、流程与合规

9.1 数据权限

角色数据范围典型权限
集团资金管理员全集团查看全部公司/项目/账户，生成集团报表，配置预警。
子公司财务本公司查看本公司账户、专户、项目资金，编制资金计划。
项目财务本项目查看项目账户、专户、回款、支出，维护项目资金数据。
审批人授权范围审批资金计划、账户变更、专户释放（后续支付）。
审计/风控授权范围只读查看报表、审计日志、异常记录，不可修改业务数据。
运维设备/任务维护 Agent、UKey、采集任务，不查看资金明细。

9.2 流程与留痕

  • 账户开立、变更、冻结、销户：申请—审批—备案—平台登记。
  • 专户资金释放：项目节点/监管材料—财务复核—负责人审批—银行办理—平台登记。
  • UKey 保管与交接：领用、归还、交接人、时间、附件。
  • 资金日报：生成—复核—发布—归档。
  • 关键操作全部写入审计日志，支持按人、时间、账户、项目查询。

9.3 国企与地产合规要点

  • “三重一大”事项与资金审批留痕。
  • 银行账户开立、变更、撤销的审批和备案。
  • 资金专户监管要求、专款专用、最低留存和释放条件。
  • 大额资金支付联签、双人复核、UKey 分管。
  • 国资监管报表：账户数量、资金集中度、融资成本、担保余额。
  • 审计要求：数据来源可追溯、报表版本可追溯、操作不可抵赖。

10集成、部署与安全

10.1 集成范围

系统集成内容阶段
银行 UKey/网银流水、回单、余额采集（现有 Agent）。一期
银行直连/银企直连账户余额、流水、支付指令、回单。二期/三期
监管平台预售监管资金、释放节点、监管额度（如可对接）。二期
ERP/财务系统组织、供应商、客户、预算、凭证、项目。二期
OA/审批系统资金计划、账户变更、付款审批。二期

10.2 部署建议

  • 集团私有云或客户机房部署，数据库与文件存储独立备份。
  • 采集 Agent 部署在客户侧 Windows 机器，只允许出站 HTTPS。
  • Web 端不直接暴露数据库；通过反向代理/网关访问。
  • 生产、测试、培训环境分离；上线前做数据迁移演练。

10.3 安全要求

  • 账号密码、UKey PIN、银行凭据加密存储，最小权限访问。
  • 支付相关操作必须双人复核、审批留痕、IP/设备绑定。
  • 操作日志、登录日志、导出日志保留不少于审计要求期限。
  • 备份、恢复、灾备演练；敏感数据脱敏展示。
  • 按等保/集团安全要求进行渗透测试和漏洞整改。

阶段周期主要内容交付物

阶段 1 司库 1.06–8 周组织/项目/账户主数据、专户台账、余额三分、资金驾驶舱、资金日报、专户/项目/账户报表、预警。可上线系统、数据迁移、UAT 报告、培训材料。
阶段 2 计划与审批6–8 周资金计划、计划执行、差异分析、审批流、账户生命周期、ERP/OA 集成。计划模块、审批流、集成接口、验收报告。

11.2 一期工作包

  1. 组织、项目、账户、专户主数据模型与页面。
  2. 余额快照扩展：账面、可用、受限、最低留存。
  3. 专户台账与专户预警规则。
  4. 资金驾驶舱首页改造。
  5. 资金日报、专户台账、项目资金表、账户清单、收支明细、采集健康度。
  6. 角色与数据权限、审计日志。
  7. 历史数据迁移、UAT、培训、上线。

11.3 验收标准

  • 账户覆盖率：纳入平台的银行账户达到客户确认清单的 100%。
  • 专户完整率：专户类型、监管方、受限金额、最低留存、释放条件完整率 ≥ 95%。
  • 数据及时性：资金日报在约定时间前生成；账户数据超过阈值未更新时产生预警。
  • 余额准确性：账面、可用、受限与银行/监管口径核对一致；差异有说明。
  • 报表可用性：六类一期报表可生成、可导出、可按权限查看。
  • 权限与审计：越权访问被阻止；关键操作可追溯。
  • 用户验收：财务、项目、审计关键用户完成 UAT 并签字确认。

12风险与应对

风险影响应对
专户监管口径不统一可用余额和预警失真调研阶段逐户确认；系统支持按账户配置公式和人工调整；保留调整记录。
银行/监管数据获取困难专户数据不完整优先 UKey/网银采集；无法采集的专户支持手工台账和导入，并标记数据来源。
历史数据质量差报表不可用先做账户/项目/专户清单清洗；历史流水按可用字段回填，缺口明确标注。
范围蔓延到支付周期和安全风险上升一期明确不包含支付；支付单独立项，先完成审批、直连和安全评估。
组织权限复杂越权或数据看不到调研阶段确认集团—公司—项目权限矩阵；用角色+数据范围双重控制。
SQLite 承载不足并发/报表性能问题一期同步迁移 PostgreSQL；报表快照化，避免实时大查询。
