# 财务工作流菜单与信息架构方案

版本：v0.1  
日期：2026-11-05  
范围：平台主导航、页面归组、设置页布局；不含具体业务规则改造。

## 1. 结论

当前菜单按“系统模块”组织，把自动采集、账户与 UKey、采集设备等技术入口放在主导航；财务人员日常使用的是看资金、收款、付款、对账、报表。

建议改为五组业务菜单：

**资金 → 收付款 → 对账 → 报表 → 设置**

技术配置统一收进“设置”，主导航只保留财务日常工作。

## 2. 设计原则

1. **按工作流组织**：菜单名称用财务动作，不用技术模块名。
2. **日常与配置分离**：采集任务、UKey 设备、账户绑定属于后台配置，不占主导航。
3. **一屏一任务**：设置类页面一次只展示一个区块，减少纵向堆叠。
4. **菜单不超过两级**：一级分组 + 二级页面，避免三级菜单。
5. **按角色裁剪**：出纳、会计、资金经理、管理员各看各的。
6. **旧链接可访问**：页面迁移后保留重定向，避免书签失效。

## 3. 新菜单结构

```text
资金
  资金总览
  账户与余额

收付款
  收款管理
  付款协同

对账
  智能对账

报表
  资金报表

设置
  账户与 UKey
  UKey 设备
  付款配置
  采集任务
  用户与权限
```

说明：

- 如果后续恢复司库专户，在“资金”下增加“资金专户”，不单独做一级菜单。
- 主导航日常项控制在 7 个以内；“设置”只在管理员登录时显示。

## 4. 现有页面映射

| 新位置 | 新菜单 | 现有页面 | 处理方式 |
|---|---|---|---|
| 资金 | 资金总览 | `/` 首页 | 页面标题改为“资金总览”；增加采集状态、待办数量 |
| 资金 | 账户与余额 | `/accounts` | 默认展示余额与账户状态；新增/编辑/绑定 UKey 移到设置 |
| 收付款 | 收款管理 | `/statements`、`/receipts` | 第一阶段保留“银行流水 / 电子回单”两个页签；后续合并为收款工作台 |
| 收付款 | 付款协同 | `/payments` | 保持现状 |
| 对账 | 智能对账 | `/recon` | 保持现状 |
| 报表 | 资金报表 | 待建 | 先放占位页或暂不显示 |
| 设置 | 账户与 UKey | `/accounts` 的配置部分 | 与“账户与余额”拆开，只保留维护动作 |
| 设置 | UKey 设备 | `/devices` | 原“采集设备”改名并移入设置 |
| 设置 | 付款配置 | `/payment-settings` | 从付款协同的「采集配置」弹窗进入；账户主数据、出纳分配、收款账户库仍在此页 |
| 设置 | 采集任务 | `/tasks` | 原“自动采集”移入设置；总览页只显示状态 |
| 设置 | 用户与权限 | `/settings` 部分 | 补角色与菜单可见性，现有 `role` 字段尚未用于菜单过滤 |

| 资金总览 | ✓ | ✓ | ✓ | ✓ |
| 账户与余额 | ✓ | ✓ | ✓ | ✓ |
| 收款管理 | ✓ | ✓ | ✓ | ✓ |
| 付款协同 | ✓ |  | ✓ | ✓ |
| 智能对账 |  | ✓ | ✓ | ✓ |
| 资金报表 |  | ✓ | ✓ | ✓ |
| 设置 |  |  |  | ✓ |

权限注意：

- 菜单隐藏只是界面层，后端接口必须同时校验角色，不能只靠前端隐藏。
- 当前 `app_user.role` 字段已存在；菜单、页面和 API 已按角色过滤，后续只需接入更细的账套/公司范围。
- 账套/公司范围建议与角色同时生效，避免出纳看到其他主体的账户。

### 5.1 已落地权限

- 角色：管理员 / 资金经理 / 出纳 / 会计；旧 `user` 角色按资金经理兼容。
- 菜单、页面和 API 路径三层同时校验。
- 资金经理：全部业务菜单，无平台管理。
- 出纳：资金、收付款，无对账和平台管理。
- 会计：资金、流水回单、对账，无付款和平台管理。
- 账户新增、编辑、删除只允许管理员和资金经理；出纳可手动采集，会计只能查看流水和对账。
- 平台管理、付款配置、采集任务、UKey 设备只允许管理员。

## 6. 页面布局调整

### 6.1 设置页

- 顶部二级页签：账户主数据 / 采集账号 / 出纳分配 / 收款账户库。
- 一次只显示一个区块，减少长页面。
- 5 个指标卡改为一条紧凑摘要：

```text
41 账户 · 19 可付款 · 16 贷款户 · 6 监管户 · 37 子账簿
```

- 表格全宽、表头吸顶、去外层卡片边框，只保留行分隔线。

### 6.2 资金总览

- 顶部保留资金余额摘要。
- 采集状态做成一个状态条，例如“采集正常 / 3 个账户待更新”，点击进入“设置 → 采集任务”。
- 待确认账户、待审核付款、待对账做成待办列表，直接跳转到对应业务页。

### 6.3 账户与余额

- 默认是财务视角：账户余额、可用状态、最近采集时间。
- 新增账户、绑定 UKey、修改采集计划等动作收进“设置 → 账户与 UKey”。
- 需要编辑时，管理员从设置页进入，不在日常页面暴露技术字段。

### 6.4 平台管理设置壳

- 主侧边栏只保留一个“平台管理”入口，普通用户不可见。
- 进入后使用左侧二级菜单：用户与权限 / 系统维护。
- 用户与权限：用户列表、创建用户、调整角色、启停账号、重置密码。
- 系统维护：运行状态、租户上下文、采集程序、账户安全和操作记录。
- 角色：管理员 / 资金经理 / 出纳 / 会计，旧普通用户按资金经理兼容。

### 6.5 付款采集配置弹窗

- 付款页只保留单据列表；单据表格上移，移除顶部采集/导入操作条和指标卡。
- 「采集配置」弹窗整合：明源云采集账号、定时采集、立即采集、Excel 导入、最近采集任务。
- 定时采集支持启用/停用、5 段 cron 和每次条数，复用现有调度器；本地模式自动执行，Agent 模式由客户机领取。
- 「采集任务」页增加「银行采集 / 明源云付款」两个页签，明源云任务共用状态筛选、分页和自动刷新，弹窗内可跳转查看全部。
- 侧边栏不再保留“付款配置”入口；管理员从弹窗底部进入完整的账户主数据、出纳分配和收款账户库页面。
- 非管理员只能查看采集账号状态，不能修改账号或进入完整配置页。

## 7. 实施阶段

### 第一阶段落地说明（2026-11-05）

已上线四组菜单：资金 / 收付款 / 对账 / 设置。

- 账户页暂以“账户管理”承载余额与配置，第二阶段再拆“账户与余额 / 账户与 UKey”。
- “收款管理”先保留“银行流水 / 电子回单”两个入口，聚合页在第三阶段建设。
- “资金报表”和“用户与权限”尚未建页，暂不放入菜单。
- 原“自动采集”“采集设备”“付款设置”已分别改为“采集任务”“UKey 设备”“付款配置”，统一收进设置。

### 第一阶段：菜单骨架（低风险）

- 重排侧边栏分组与名称。
- 把自动采集、设备、账户配置、付款设置移入“设置”。
- 增加旧 URL 重定向，保留现有路由。
- 总览页增加采集状态提示。
- 不改数据库，不改业务逻辑。

### 第二阶段落地说明（2026-11-05）

- 付款配置页已改为一行摘要 + 四个页签（账户主数据 / 采集账号 / 出纳分配 / 收款账户库），一次只显示一个区块。
- 付款配置页去掉面板外框和卡片背景，表格直接落在页面内容区。
- 账户管理页的四个指标卡改为一条摘要条，账户卡片和设备页签保持不变。
- 账户页拆分、收款管理聚合页、资金报表和角色权限仍在后续阶段。

### 第二阶段：页面布局

- 设置页改为顶部页签 + 单区块。
- 付款设置页去卡片化，指标改成摘要条。
- 账户页拆成“账户与余额”和“账户与 UKey 配置”两个入口。
- 表格统一吸顶表头、分页、行悬停。

### 第三阶段：角色与新页面

- 按角色过滤菜单与接口权限。
- 新建“收款管理”聚合页（流水 / 回单 / 待认领）。
- 新建“资金报表”页面。
- 如恢复专户，在“资金”下增加“资金专户”。

## 8. 验收标准

1. 主导航不超过 5 个分组，日常菜单不超过 7 个。
2. 主导航不出现“采集”“设备”“UKey 配置”等技术词。
3. 财务人员从首页到付款、对账、流水不超过 3 次点击。
4. 所有菜单链接可访问，旧链接有重定向，不出现 404。
5. 普通财务看不到系统设置；管理员可见。
6. 1440px 宽度下主要表格不出现横向溢出。
7. 页面容器层级不超过两层，不再出现卡片套卡片。

## 9. 风险与兼容

- **路由迁移**：旧地址保留 302 重定向，至少保留一个版本周期。
- **并发修改**：当前工作区有多个页面同时在改，实施前需要先冻结侧边栏和模板。
- **权限安全**：角色过滤必须同时落在后端接口，不能只隐藏菜单。
- **专户模块**：当前工作区的司库页面与路由已删除；是否恢复需要先确认，避免恢复死链接。
